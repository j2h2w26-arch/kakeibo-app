# セキュリティ運用方針

最終更新: 2026-10-02（段階②③のDraft改善を含む。本番反映とは別）

## Supabase Freeプランの継続

このアプリは家族内の少人数利用であり、SupabaseはFreeプランを継続する。Freeプランでは、漏洩済みパスワードとの照合機能（Leaked password protection）を有効化できないため、現時点では未有効の警告を受容する。プラン変更を前提にした実装や運用は行わない。

2026-09-30に本番組織のプランが`free`であることと、Security Advisorの`auth_leaked_password_protection`警告を再確認した。[公式仕様](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)でも、この機能はPro以上に限定される。今回の有効化依頼は**プラン制約により保留・未完了**とする。警告が消えた、有効化できた、という扱いにはしない。契約・課金・Auth設定は変更していない。

パスワード強度要件を強化しても、公式仕様では既存ユーザーは現在のパスワードでログインできる。新規登録・パスワード変更は新しい要件の対象となり、既存ユーザーのログインでは弱いパスワードの情報が返る場合がある。実際の有効化時には使用中のクライアントライブラリの戻り値と画面動作を検証する。今回はFreeプランのため、この設定を有効にした実ログイン検証は行っていない。

漏洩パスワード照合のための外部メールサービス契約は、公式手順に必須条件として記載されていない。再設定メールやSMTP設定とは別の機能である。今回パスワード再設定メールの送信・再設定フローの追加作業は行わない。

調査根拠・未確認範囲は[認証レビュー](auth-security-review-2026-09-30.md)、段階的な開発と本番承認のルールは[決定記録](DECISIONS.md)を参照する。

代わりに、次の既存対策と運用を維持する。

- アプリ内に新規登録画面を設けず、管理者が作成した家族2人のアカウントだけを使う。
- `app_members`の許可リストと全対象テーブルのRLSで、登録済みメンバー以外の家計データへのアクセスを拒否する。
- 2人とも、他サービスで使い回していない長いパスワードを使う。パスワードはリポジトリ、Issue、チャットへ保存しない。
- 不審なログイン、端末紛失、パスワード流出の疑いがある場合は、Supabase Authで該当ユーザーのセッションを失効させ、パスワードを変更する。

次の場合は、この判断を再確認する。

- 利用者を家族2人より増やすとき
- 外部公開や一般ユーザー登録を追加するとき
- 金融機関との連携、決済、本人確認情報など、現在より機密性の高いデータを扱うとき
- Supabaseのプランまたは漏洩パスワード保護の提供条件が変わったとき

## 端末内データ

オフライン表示用の家計データはブラウザのローカルストレージへ保存するが、保存から24時間を過ぎたデータは復元に使わず、次回起動時に削除する。ログアウト時には、家計データとメンバー情報の端末キャッシュを削除する。共有端末では利用後に必ずログアウトする。

段階②の家計キャッシュv12はユーザーIDも照合し、別ユーザー・所有者不明の旧版は復元しない。ログアウト後の古い通信応答も書込み拒否する。端末データは暗号化保証なし。オフラインでサーバーのメンバー除外を即時反映はできないため、紛失時はAuth側の対応に加え端末ロック等も必要。PWA更新では家計/認証データを一括消去しない。

## レシート画像

レシート画像は非公開Storageバケットへ保存し、認証済みの家族メンバーだけが短時間の署名付きURLで閲覧する。支出削除時はデータベースの記録を先に削除し、画像削除に失敗しても削除済み支出が壊れた画像参照を残さない。
