# ② 夫婦2人の検証記録

確認日: 2026-10-01。**自動検証は実施、実アカウント・実機E2Eは未確認**。本番データの追加・変更・削除、パスワード変更・再設定メール送信は行っていない。

## 現状・変更・影響

- 本番の読み取り専用確認: メンバー2人、メール確認済みメンバー2人。公開テーブル31すべてRLS有効、Realtime対象29テーブル、receiptsバケット非公開。
- 取得中のログアウト後、古い応答がキャッシュへ書き戻される経路を修正。ログアウト・アカウント切り替え・アンマウント時に通信結果を無効化し、遅延コールバックからの再取得も拒否する。
- キャッシュv12をユーザーIDに紐付ける。別ユーザー・所有者不明の旧版・破損・24時間以上前・未来日時のキャッシュは復元しない。
- AuthのSIGNED_OUTイベントでもキャッシュを消去。セッションとメンバーIDが一致する場合だけデータ・通知を有効にする。古い初期セッション取得が新しいAuthイベントを上書きしない。
- 旧版の端末キャッシュは破棄するため、初回更新後はオンラインでの再取得が必要。同一ユーザーの新キャッシュは24時間未満ならオフライン閲覧を継続できる。サーバーの保存済みデータは削除しない。
- DBスキーマ・RLS・Auth設定・パスワード回復機能は変更しない。

## 自動検証の範囲と限界

実行結果: `npm test` 99件成功・失敗0、`npm run lint` 成功、`npm run build` 成功（既存の500kB超チャンク警告あり）。ローカルは接続情報未設定のビルドで白画面を検出し、公開クライアント用URL/キーだけを一時環境変数で渡して再ビルドした。新版JSによるログイン画面表示を確認し、新しいブラウザーエラーはなかった。実ログインやデータ更新はしていない。

ブラウザー確認中、初回再読込では旧Service WorkerのJSが残り、次の再読込で新版へ切り替わった。この更新導線は段階③で改善する。Previewの配信結果とURLはPR本文に記録する。

`npm test` はキャッシュ競合・所有者分離の回帰テストと、PGliteの隔離Postgresでの検証を含む。

| 対象 | 自動検証 |
|---|---|
| 買い物・在庫・Wish・人生ToDo・手動ポイ活 | 夫→妻、妻→夫の作成・閲覧・編集・削除 |
| 人生設計 | 双方の共同編集、アーカイブ・復元。既存テストでルート等の整合性も検証 |
| お金 | 貸借作成、配偶者の返済、過剰返済拒否、取消、支出の共有閲覧 |
| 家事 | 配偶者による完了、履歴共有、同日二重完了の重複防止 |
| 個人設定・履歴 | 通知・ポイ活設定の分離、他人名義の完了記録拒否、他人の完了・コメント削除拒否 |
| レシート | SQL上の非公開設定・共有閲覧・他人のパスへのアップロード拒否 |
| 未ログイン・家族以外 | 全31公開テーブルで閲覧結果ゼロまたは権限拒否、主要書込み・RPC拒否 |

テスト用に初期3テーブルとAuth/Storageの最小構造を作り、現行マイグレーションを適用する。外部通信を伴うCron設定は除外。AuthのJWT署名・実パスワードでのログイン・実ファイルアップロード・署名付きURL・WebSocket同期・実機ブラウザは、このSQLテストでは検証できない。空テーブルの閲覧拒否だけでは全操作の安全性を証明できないため、実データを置いた主要操作も別途検証している。
