# レシートOCRの現状確認（段階⑤）

確認日: 2026-10-02。既存機能の監査と小修正。新しいOCR契約、画像送信、本番設定変更はしていない。

## 実装済みなので省略する開発

`src/lib/receiptOcr.js`はTesseract.js 7.0.0で日本語/英語の画像を端末内認識し、店名・日付・金額・品目を候補として抽出する。`ExpensePanel.jsx`は写真プレビュー、進捗、修正可能な候補、明示的な「内容を確認して保存」を持つ。読み取りだけでは支出も画像もサーバーへ保存しない。保存中/読み取り中/オフラインは保存ボタンを無効化。読めなければ手入力できる。画像は5MBまで。PDFは対象外。HEIC等の認識互換性は保証せずJPEG/PNGを推奨する。

## データの行き先と保持

| データ | 送信・保存先 | 保持・制約 |
|---|---|---|
| 選択した写真、認識中の画像 | ブラウザーのBlob/FileReaderとWeb Worker | 外部OCR APIへ送らない。フォームを閉じるとプレビューURLを解放、認識終了でWorkerを終了。OS/ブラウザーの物理的な即時消去までは保証しない |
| 言語モデル | jsDelivrから端末へGET、IndexedDBへキャッシュ | 初回/キャッシュ消失時に通信。画像は含まないがCDNにはIP等の通信情報が渡る。モデルキャッシュに明示的な期限はなくブラウザー管理 |
| Worker/WASMコード | 自サイトの`/ocr/`から取得 | ビルド時に固定依存からコピー。PWAプリキャッシュ対象外で、完全オフラインOCRを保証しない |
| 確認後の写真 | 既存Supabaseの非公開`receipts` | 保存操作で初めてアップロード。自動保存期限なし。支出削除時に画像も削除を試み、失敗は警告。孤立画像の自動清掃は未実装 |
| 確認後の項目 | 既存`household_expenses` | 人が修正した内容を保存。認識全文を自動保存しない |

非公開バケットと既存RLSを変更しない。写真の閲覧は60秒の署名URLで、署名の期限やアップロードのcacheControlは画像本体の保存期限ではない。有効な署名URLを第三者に渡さない。アップロード後に支出登録が失敗した場合も画像除去を試みるが、除去失敗による残存の可能性はある。

依存コード確認: `tesseract.js/src/worker/browser/loadImage.js`はFile/BlobをFileReaderで読む。`src/worker-script/index.js`の既定モデルURLは`https://cdn.jsdelivr.net/npm/@tesseract.js-data/${lang}/4.0.0_best_int/${lang}.traineddata.gz`。`src/worker-script/browser/cache.js`はidb-keyvalを使用する。依存更新時は再確認する。

## 費用とサービス

- [Tesseract.js公式](https://github.com/naptha/tesseract.js): Apache-2.0のブラウザー内OCR。外部OCR APIの従量課金なし。[構成の公式説明](https://github.com/naptha/tesseract.js/blob/master/docs/local-installation.md)。
- 保存写真は既存のSupabase容量・通信枠を使う。[公式料金](https://supabase.com/pricing)確認時、Freeはファイル1GB、Egress 5GB、Cached Egress 5GB。OCRが無料でも保存・通信容量が無制限という意味ではない。
- Freeを維持し、自動の有料化・外部OCRへの切替はしない。枠不足なら利用者へ相談する。CDN/ホスティング停止やネットワーク不調時の認識成功は保証しない。

## 今回の変更と検証

- 「税込合計 ￥1,100」が税ラベル除外に巻き込まれnullになる不具合を回帰テストで再現。税込合計だけを除外対象から外す。
- 消費税・内税・外税・小計・割引・釣銭は引き続き合計候補にしない。税額が同じ行にある曖昧なケースは自動確定しない。
- UIに言語モデルの外部ダウンロードと、確認保存後の写真送信/保持を明記。
- テストは合成文字列の解析と既存隔離DBテスト。実画像の認識精度、実Storageのファイル保存/署名配信を証明するものではない。
