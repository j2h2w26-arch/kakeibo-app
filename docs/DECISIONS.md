## 2026-10-06 — 端末同意と受信を先行し、配信は無効のまま分離

- ⑥-2は本人同意UI・ログアウト/解除・受信SWのみ。送信機能/テスト通知ボタン/Cronは次段階。本番移行・実購読は行わない。
- Viteの公開フラグとVAPID公開鍵が未設定なら準備中。秘密鍵をクライアントへ追加しない。
- 既存generateSWへimportScriptsで受信だけを追加し、確認後更新とオフラインシェルを保つ。別scopeのSWは作らない。
- 時刻設定の保存とOS通知の同意を分離。登録処理は開始時のJWTとアカウント世代に固定する。解除はローカル・ブラウザー・サーバーの部分失敗を区別し、ログアウトを無期限に待たせない。
- サーバー登録の確認に失敗した端末は停止を試みる安全側の方針。オフライン起動等の後に再登録が必要になる場合を明記。到着保証・完全取消・実機合格とは表現しない。
- [実装・検証・残作業](push-device-controls.md)。新しいDB変更や外部サービス契約はない。

## 2026-10-05 — Push方針の承認を受け、登録/解除の土台を分離

- 利用者の「よい！！」で、端末別同意・朝夕・未完了時のみ一般文・既存Free基盤の方針が承認された。2026-10-02の設計承認待ちを解除。本番反映の承認ではない。

- private側の限定的なSECURITY DEFINERに本人/メンバー検証を置き、公開RPCはSECURITY INVOKERとする。鍵やendpointを返さず、匿名EXECUTEと表への直接権限を明示的に拒否。

- 既存通知設定の変更や購読のseedは行わない。新たな外部通信/課金なし。[検証範囲と残作業](push-subscription-foundation.md)。

## 2026-10-01 — PWAは通知後の明示更新にする

- 保存途中の入力を保護するため、SWの新版取得と画面の再読込を分離する。自動再読込せず、保存確認の操作を必須にする。
- 別タブで有効化しても、その画面は強制再読込しない。オフライン・保存中は更新不可とする。
- アプリシェルのキャッシュは維持し、キャッシュ全削除や認証セッション消去を更新導線にしない。
- 通知未搭載の旧版は初回だけ全タブを閉じて開き直す必要がある。[検証と制約](pwa-updates.md)を参照。

## 2026-09-30 — 段階ごとのDraft PRと本番承認

- 状態: 利用者の指示として適用中。
- 順序: 認証 → 夫婦2人の動作確認 → PWA更新対策 → README・仕様書 → レシートOCR → バックグラウンドPush通知。

- 各段階で`npm test`、`npm run lint`、`npm run build`を実行する。DB変更時はRLS、匿名・非メンバー拒否も検証する。
- 既存データ、RLS、非公開画像保存を維持し、秘密鍵はクライアント・Gitに置かない。
- パスワードは見つかったため、再設定メール送信と再設定フローの追加作業は不要。
- 新たな契約・課金、OCR画像の外部送信、Push通知仕様は、事前に利用者の判断を得る。

- 状態: 調査済み、有効化は未完了。Free継続の既存方針を維持。
- 根拠: 本番組織はFree、Security Advisorに無効警告あり。[Supabase公式仕様](https://supabase.com/docs/guides/auth/password-security)はPro以上での提供を明記。

- 影響: 警告と漏洩パスワード照合の欠如が残る。既存の家族メンバー許可リスト・RLSは照合機能の代替ではないが、引き続きデータアクセスを制御する。
