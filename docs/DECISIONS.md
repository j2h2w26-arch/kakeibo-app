# 決定記録

現行コードとサービスの確認結果、および明示された運用方針を記録する。過去の設計チャットだけを根拠に、未実装・未検証の内容を完了扱いにしない。

## 2026-10-01 — 端末キャッシュの所有者と非同期応答の分離

- 個人設定も含むため、家計スナップショットをユーザーID付きキャッシュv12へ変更。所有者不明の旧版は復元しない。初回だけオンライン再取得が必要。
- ログアウト・アカウント変更・アンマウント後の古い応答は画面だけでなくキャッシュへの書込みも拒否する。
- 実機ログイン・Realtime同期と隔離DBの権限テストを明確に分離する。実機未確認のまま完了としない。[検証記録](two-member-verification.md)を参照。
- この段階はクライアントとテストのみ。本番DB・RLS・認証設定は変更しない。

## 2026-09-30 — 段階ごとのDraft PRと本番承認

- 状態: 利用者の指示として適用中。
- 順序: 認証 → 夫婦2人の動作確認 → PWA更新対策 → README・仕様書 → レシートOCR → バックグラウンドPush通知。
- 各段階で現状、変更と影響、実装、検証、Draft PR・Preview、結果報告を区切る。
- `main`へ直接pushしない。PRとPreviewを利用者が確認し、明示的に了承するまでマージ・本番反映を行わない。Auth設定・本番DB・Edge Functionsの変更も本番反映に含む。
- 各段階で`npm test`、`npm run lint`、`npm run build`を実行する。DB変更時はRLS、匿名・非メンバー拒否も検証する。
- 既存データ、RLS、非公開画像保存を維持し、秘密鍵はクライアント・Gitに置かない。
- パスワードは見つかったため、再設定メール送信と再設定フローの追加作業は不要。
- 新たな契約・課金、OCR画像の外部送信、Push通知仕様は、事前に利用者の判断を得る。

## 2026-09-30 — 漏洩パスワード保護はプラン制約により保留

- 状態: 調査済み、有効化は未完了。Free継続の既存方針を維持。
- 根拠: 本番組織はFree、Security Advisorに無効警告あり。[Supabase公式仕様](https://supabase.com/docs/guides/auth/password-security)はPro以上での提供を明記。
- 判断: 調査結果をDraft PRで提示する。プラン変更・課金や本番設定変更は実施しない。無料プラン上の独自パスワード照合を、標準機能の有効化と同等として扱わない。
- 影響: 警告と漏洩パスワード照合の欠如が残る。既存の家族メンバー許可リスト・RLSは照合機能の代替ではないが、引き続きデータアクセスを制御する。
- 再検討条件: 利用者が有料化を明示的に選択した場合、または公式の提供条件が変わった場合。
- 詳細: [認証レビューと残開発の現状](auth-security-review-2026-09-30.md)。
