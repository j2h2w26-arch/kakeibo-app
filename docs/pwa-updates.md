# ③ PWAの更新とオフライン表示

確認日: 2026-10-01。本番未反映。

## 再現と原因

旧実装はVite PWAのautoUpdateと自動挿入registerSW.jsのみで、画面上の更新通知・利用者が新版へ切り替える導線がなかった。ローカルでビルドを入れ替えたところ、初回再読込は旧JS、次の再読込で新版JSとなった。更新取得、SWの有効化、開いているページの再読込は別のタイミングなので、ビルド成功だけでは新版が表示されることを保証しない。

## 決定・影響

- `registerType: prompt`、`skipWaiting: false`。SW登録はクライアント側の単一更新管理に集約し、自動挿入を無効化する。
- 新版の待機を検知して画面上部に通知。「新版に切り替える」→未保存入力の注意→「保存済み・更新する」の明示操作だけで切り替える。
- 保存処理中・オフライン中は更新ボタンを無効化。適用失敗・15秒タイムアウトは現在の画面を保持し、再試行を案内。
- 他のタブのSW有効化ではそのタブを強制再読込しない。画面ごとに利用者の確認を待つ。他の画面の入力も更新前に保存する案内を表示する。
- 起動時・接続復帰・画面復帰・表示中の1時間ごとに確認。復帰イベントは1分間隔に抑制。「更新を確認」は手動実行できる。
- SWスクリプトは`updateViaCache: none`、配信側の`/sw.js`・`/index.html`・`/`も再検証させる。認証情報や家計データのキャッシュキーは変更・削除しない。
- 既存のアプリシェルのプリキャッシュとオフライン用index.htmlは維持する。OCR資産をプリキャッシュへ加えたり、Supabase APIやレシートを公開キャッシュへ保存したりしない。
- 画面上にビルドIDを表示し、古い版かを確認可能にする（Vercelではcommit先頭7文字）。

## 初回移行の注意

今回の通知コード自体がまだ読み込まれていない旧版には、あとから通知を表示できない。初回のみ、入力を保存し、このアプリの全タブ・ホーム画面アプリをいったん閉じて開き直す。ブラウザーのデータ全削除やSW登録解除を通常手順にしない。更新通知搭載版以降は画面の導線で更新する。

別タブで古いJSのまま長時間使う場合、旧版の遅延読み込み資産は配信環境によって取得できなくなる場合がある。そのため更新前に全画面の入力保存を案内する。すべてのブラウザーでバックグラウンド中の更新確認時刻を保証しない。

## 検証結果

- 自動: 更新通知、明示承認/オンライン/保存完了の条件、他タブ更新、初回導入、失敗、タイムアウト、接続断、復帰抑制を追加テスト。
- ブラウザー（ローカルの実SW）: qa-v1を開き架空メール文字列を入力、qa-v2へビルド差し替え。「更新を確認」で通知し、入力を保持。「戻って保存する」で保持。「保存済み・更新する」でqa-v2に切替。別タブはqa-v1の入力を保持。
- 配信サーバーを実際に停止し再読込: キャッシュからログイン画面を表示、更新確認の失敗を表示。OS全体のオフラインや、ログイン後の家計データ表示の実機検証とは区別する。
- 更新前後の正常配信中はブラウザーのconsole errorなし。検証用の入力は送信していない。
- iPhone/Android/Surfaceでのホーム画面PWAの切替、実ユーザーの未保存フォーム、端末オフラインからの復帰は未確認。
- `npm test` 107件成功、`npm run lint` 成功、`npm run build` 成功。既存の500kB超チャンク警告は残る。
- Preview URL・配信状態はDraft PR本文に記録。本番マージ・公開は承認待ち。

## 実機での確認

1. 入力保存後に全タブを閉じて開く。画面上の「アプリの更新」と版番号を確認。
2. 次回Preview更新時、入力途中のまま更新確認。勝手にリロードしないことを確認。
3. 更新ダイアログをキャンセル→入力保持→保存→更新→新版の版番号を確認。
4. 別タブの入力保持、機内モードでの表示と更新ボタン無効、接続復帰を確認。

公式根拠: [Vite PWA prompt](https://vite-pwa-org.netlify.app/guide/prompt-for-update)、[SW update](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerRegistration/update)、[controllerchange](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerContainer/controllerchange_event)。
